User manual: from repositories to a reviewed resume

2026-11-23 · For the user who runs the pipeline in Claude Code · Design: Ingest → Ground truth

Overview

This project turns your work history into resume bullets you can defend. You give it a configuration file for one company. The LLM then loads your repositories, writes one evidence file per project, and interviews you to confirm the Summary. Last, it writes the resume YAML from the evidence files and reviews the built PDF. Every resume bullet traces to a cited claim in an evidence file.

TaskYou doThe LLM doesResult
1 · ConfigureWrite mapping.yml, then start ingestClones repos, downloads Jira tickets, counts your commitsraw/<company>/
2 · DistillStart distill for one project, review the fileReads your code and tickets, writes a cited, anonymised file with a draft Summaryevidence/<company>/<yyyy>-<id>.md
3 · VerifyAnswer questions, confirm the bulletsFolds your answers into the file, rewrites the SummarySame file, with reviewed: set
4 · To resumeApprove the plan, check the bulletsWrites the resume YAML from the evidence, with a trace comment per bullet, then builds itresume/data/resume.yml or resume/versions/<slug>/resume.yml
5 · ReviewRead the review, pick the fixesMeasures the PDF and checks every bullet against its evidenceresume/review/<slug>.html

Before you start

The plugin holds the six skills.

  1. Open a terminal at the repository root.
  2. Install the pinned tools: mise install.
  3. Check the tools: uv --version and claude --version.
  4. Install the Python dependencies: uv sync.
  5. Install the plugin for this repository: mise run plugins.
  6. Start Claude Code: claude.
  7. Type /resume-evidence and make sure the six skills appear: ingest, distill, verify, to-resume, resume, review-resume.

To try the plugin for one session without installing it, start Claude Code with claude --plugin-dir ./.claude-dev.

If you change a skill file, run claude plugin marketplace update resume-builder-local.

How to prompt

The LLM runs a skill only when you type its command. A request in plain words, such as "distill my project", does not start the skill. Write the command first, then its arguments, then any context in plain words on the same message:

/resume-evidence:<skill> <arguments> <context for the LLM>

Context helps the LLM ask fewer questions: what you know about the project, what to focus on, what to leave out. Each step below gives example prompts. Replace company-a and retail-shelf-cv with your own company slug and project id.

1 · Configure and ingest

One company has one mapping.yml. It tells the scripts who you are in git, where your repositories are, and how to name each project in public.

Warning: mapping.yml holds real client names and a Jira API token. Keep it under raw/. Git ignores everything in raw/ except the example file.

Write mapping.yml

  1. Pick a short slug for the company, for example company-a.
  2. Copy the example: mkdir -p raw/company-a && cp raw/repository-mapping.example.yml raw/company-a/mapping.yml.
  3. Set company to the slug.
  4. Under me, list every git author name and email you committed with.
  5. If you want Jira tickets, fill in jira. Otherwise, delete the jira block.
  6. Add one entry under projects for each project.
  7. For each project, list every repository URL under sources.

You can also ask the LLM to do the copy. It copies the example and stops; you fill in the values. The LLM never edits mapping.yml after that. When it needs a change, it tells you what to change.

company: company-a                  # folder name under raw/ and evidence/

me:                                 # how to find your commits
  names: [jane, jdoe]               # case-insensitive, matches as a substring
  emails: [jane@company-a.example]  # case-insensitive, exact

jira:                               # optional
  site: company-a.atlassian.net
  email: jane@company-a.example
  api_token: <token>                # https://id.atlassian.com/manage-profile/security/api-tokens

projects:
  - id: retail-shelf-cv             # slug in paths
    internal_name: Acme Shelf       # real name; never written to evidence/
    title: Retail Shelf Computer-Vision Analytics Platform  # public name
    sources:
      - git@bitbucket.org:company-a/shelf-mono-repo.git
FieldRequiredUsed for
companyYesFolder name under raw/ and evidence/
me.names, me.emailsYesMatching your commits. A missing alias hides commits.
jiraNoDownloading the tickets assigned to you
projects[].idYesPaths: raw/<company>/<id>/ and the evidence file name
projects[].internal_nameYesFinding Jira tickets. Banned from evidence.
projects[].titleYesThe anonymised name in the evidence file
projects[].sourcesYesGit URLs to clone

Example prompts: configure

/resume-evidence:ingest company-a

Check raw/company-a/mapping.yml before you clone. List each field that is
missing or still holds an example value.

I committed with two identities: my work email and my personal one. Tell me
which repos show zero commits from either.

Run ingest

  1. In Claude Code, type /resume-evidence:ingest company-a.
  2. Wait for the report. It shows one table per project.
  3. For each repository marked failed, fix the URL or your git access.
  4. For each repository with zero commits of yours, add the missing name or email to me, or fix the URL.
  5. If you changed mapping.yml, run ingest again.

Ingest only copies data. It clones each source into raw/<company>/<id>/<repo-name>/, or fetches it if it is already there. It writes your commit counts to raw/<company>/summary.json and Jira tickets to raw/<company>/jira/<yyyy>.json. A Jira project with your tickets but no entry in mapping.yml goes into TODO.md as a project to add. You can run ingest again at any time to pick up new commits.

You can also run the script yourself: uv run scripts/ingest_repos.py company-a.

Example prompts: ingest

/resume-evidence:ingest company-a

/resume-evidence:ingest company-a
I added two repos to the retail-shelf-cv project. Fetch only what is new
and show me the commit counts for that project.

/resume-evidence:ingest company-a
The shelf-dashboard clone failed last time. I fixed my SSH key; try again.

2 · Distill

Distill reads one project's raw data and writes its evidence file: what you did, with a citation for each claim, and no real names. Run it once per project.

  1. Type /resume-evidence:distill company-a retail-shelf-cv.
  2. If you leave out the company or the project, pick one from the list the LLM shows.
  3. Wait while the LLM measures your authorship, reads the code and reads the tickets.
  4. Read the draft Summary the LLM shows first.
  5. Read the rest of the file and the list of open questions.
  6. If a claim is wrong, tell the LLM what you actually did. It records your answer as a [me: yyyy-mm-dd] citation.
  7. Confirm the file when it is correct.
  8. Review the diff and commit evidence/company-a/<yyyy>-retail-shelf-cv.md.

You do not need to answer every open question here. Verify asks them later.

Example prompts: distill

/resume-evidence:distill company-a retail-shelf-cv

/resume-evidence:distill company-a retail-shelf-cv
I joined this project in March 2025, after the first version shipped.
I owned the detection pipeline and the ingestion service. A teammate built
the dashboard, even where my name is on the merge commits.

/resume-evidence:distill company-a
Which projects in mapping.yml have no evidence file yet? Start with the
one where I have the most commits.

What distill writes

The file is evidence/<company>/<yyyy>-<id>.md, where yyyy is the year of your first commit in the project. Its sections:

SectionHolds
FrontmatterTitle, period, role, status (shipped, wip, dropped), the verified: commit read per repo, and reviewed:
SummaryThree to six resume bullets and a Remark for each; a draft until verify
ContextWho the project was for, the problem, rough scale
What I DidOne cited bullet per thing you owned, decided or built
NumbersMeasured outcomes and scale, each with its scope and source
ToolsTechnology actually used, and what was only studied
ArchitectureA Mermaid diagram and a short explanation
Not mineParts others built, named by role
Open questionsGaps git cannot answer

Citations

FormMeans
[backend:src/api 92%]Your share of the blame lines under that path
[backend@a1b2c3d]One of your commits
[KEY-123]A Jira ticket. Proves assignment, not authorship.
[me: 2026-11-23]Your own account, given on that date

Distill again after new work

  1. Run ingest for the company to fetch the new commits.
  2. Run distill for the same project.

Distill finds the existing file and starts at its verified: commits. It adds new bullets and keeps the existing ones. If the Summary is already confirmed, new bullets are marked (draft). Run verify again to confirm them.

Example prompts: distill again

/resume-evidence:distill company-a retail-shelf-cv
I ingested the commits from the last three months. Add the new work only;
keep the confirmed bullets as they are.

3 · Verify

Git shows what you did. Verify asks you what it was worth: outcomes, scale, whether it shipped. It then rewrites the Summary as confirmed resume bullets.

  1. Type /resume-evidence:verify company-a retail-shelf-cv.
  2. If you leave out the arguments, pick a file from the list. The list shows which files are reviewed and how many open questions each has.
  3. Answer each round of questions. A round has four questions or fewer.
  4. If you do not know an answer, say "don't know".
  5. To end the interview early, tell the LLM to stop.
  6. Read the rewritten Summary and the diff of the evidence sections.
  7. Correct anything wrong.
  8. Confirm the file. The LLM sets reviewed: to today.
  9. Commit the evidence file.

Example prompts: verify

/resume-evidence:verify company-a retail-shelf-cv

/resume-evidence:verify
Show me which evidence files are not reviewed yet, and how many open
questions each has.

/resume-evidence:verify company-a retail-shelf-cv
Ask about outcomes first: what shipped, and the numbers. I have the
production latency figures from our monitoring dashboard.

Example answers during the interview:

1. Shipped to production in June 2025; about 300 stores used it.
2. Don't know. The client never shared accuracy in the field.
3. Partly mine: I wrote the model training, a teammate wrote the labelling tool.
4. Don't quote the 0.65 mAP figure. Product AP50 0.92 is fine.

How to give good answers

  • Give numbers with a scope: "p95 latency fell from 800 ms to 120 ms, measured in production over a week".
  • Say if a number is a guess. The file marks it as estimated or user-reported.
  • Say if you only committed work that a teammate designed. Your account overrides git.
  • Say if a feature never shipped. The bullet then reads "prototyped" or "evaluated", not "delivered".
  • Use real names in answers if you need to. The LLM anonymises the file and runs the banned-term search before you confirm.

Each answer goes into the evidence sections first, cited [me: yyyy-mm-dd], and only then into a bullet. A "don't know" stays under Open questions with the date you were asked. If an answer names a repository or Jira project not in mapping.yml, the LLM tells you what to add and records it in TODO.md.

Use the result

Copy the bullets under ## Summary → ### Resume bullets into your resume. Read the Remarks before you choose: each one names the claim the bullet traces to, its strength, its caveat and the roles it fits.

4 · Write the resume

The resume lives in resume/. Its content is one YAML file: resume/data/resume.yml for the base resume, or resume/versions/<slug>/resume.yml for one job application. Work bullets and skills come only from evidence files. Your name, contact details, employers, job titles, dates and education come from you.

  1. Verify every evidence file you want on the resume.
  2. For the base resume, type /resume-evidence:to-resume.
  3. For one job application, type /resume-evidence:to-resume 2026-dec-acme-ml, and paste the job ad when the LLM asks.
  4. If the LLM lists unreviewed evidence files, choose: verify first, include as draft, or leave out.
  5. Give the employer name, job title and dates for each company when the LLM asks.
  6. Read the plan. Approve it, or tell the LLM what to change.
  7. Read the YAML diff and the page images in resume/build/<slug>/.
  8. Correct any bullet you cannot defend in an interview.

Each bullet in the YAML has a trace comment above it, such as # evidence/company-a/2025-retail-shelf-cv.md B2. It names the evidence file and the Summary bullet the claim comes from. Keep the comment when you edit the bullet. To reword text without the full pipeline, use /resume-evidence:resume.

Example prompts: write the resume

/resume-evidence:to-resume

/resume-evidence:to-resume
Use only reviewed evidence files. Put backend, data and LLM work first and
keep computer vision as supporting work. Fit one page.

/resume-evidence:to-resume 2026-dec-acme-ml
Here is the job ad:
<paste the job ad>
Aim the headline at "ML engineer". Tell me each requirement I can't show.

/resume-evidence:resume
Proofread the experience bullets in resume/data/resume.yml. Keep every
trace comment and change no facts.

Example answers when the LLM asks for facts that evidence does not hold:

company-a prints as "Company A Co., Ltd.". Job title: Data Scientist,
Jul 2022 – Present. Keep my header and education as they are.

To build the resume yourself:

mise -C resume run check            # check the YAML against the schema
mise -C resume run build            # base resume -> resume/build/base/classic.pdf
mise -C resume run version <slug>   # a version   -> resume/build/<slug>/classic.pdf
Warning: the build fails if the resume runs past maxPages (default 1). Cut or hide bullets before you raise maxPages.

5 · Review the resume

  1. Type /resume-evidence:review-resume for the base resume, or /resume-evidence:review-resume <slug> for a version.
  2. Open resume/review/<slug>.html in a browser. The base resume writes index.html.
  3. Fix every fail row first. Start with the Evidence traceability group.
  4. Apply the fixes you agree with through /resume-evidence:to-resume.
  5. Run the review again.

The review measures the PDF for screening, CV standards, readability, format, ATS, contrast and accessibility. It also checks that every bullet has a trace comment, claims no more than its evidence, and quotes only numbers from the evidence.

Example prompts: review

/resume-evidence:review-resume

/resume-evidence:review-resume 2026-dec-acme-ml rail
Compare the rail template with classic for this version. Focus on the
keyword match with the job ad.

/resume-evidence:to-resume 2026-dec-acme-ml
Apply fixes 1 to 3 from resume/review/2026-dec-acme-ml.html. Skip fix 4:
I keep the projects section.

Troubleshooting

SymptomCauseAction
Ingest marks a repo failedWrong URL, or no git accessClone the URL by hand to see the error. Fix it, then run ingest again.
A repo shows zero commits of yoursme lacks one of your names or emailsRun git -C raw/<company>/<id>/<repo> shortlog -sne --all. Add your missing identity to me.
Distill says there are no reposIngest has not run for that projectRun ingest for the company.
A real name appears in an evidence fileThe banned-term search missed a termTell the LLM the term. It replaces it with a placeholder and runs the search again.
The resume build says it is 2 pagesToo much textHide or cut the lowest-ranked bullets. Raise maxPages only if you want two pages.
mise -C resume says the config is not trustedmise has not trusted resume/mise.tomlRun mise trust resume.
Skills do not appear under /resume-evidenceThe plugin is not installedRun mise run plugins, then restart Claude Code.

Glossary

Authorship
Your share of a repository, per directory: your commit count and your share of git blame lines at HEAD. Distill claims only paths where your share is real.
Banned-term search
A grep of the evidence file for every real name: internal names, repo names, hosts, the Jira site, clients and people. It passes at zero hits.
Evidence file
The anonymised, cited record of one project at evidence/<company>/<yyyy>-<id>.md. The ground truth for every resume claim.
mapping.yml
The configuration for one company at raw/<company>/mapping.yml. Only you edit it.
Open question
A gap in an evidence file that git and Jira cannot answer. Verify asks you each one.
Plugin
resume-evidence, the local Claude Code plugin in .claude-dev/ that holds the six skills.
Skill
A set of instructions the LLM follows when you type its command, for example /resume-evidence:distill.
Trace comment
A YAML comment above a resume bullet that names its evidence file and Summary bullet, for example # evidence/company-a/2025-retail-shelf-cv.md B2.
Summary
The top section of an evidence file: three to six resume bullets and their Remarks. A draft until verify sets reviewed:.
TODO.md
raw/<company>/TODO.md: projects to add to mapping.yml and leads for distill.
